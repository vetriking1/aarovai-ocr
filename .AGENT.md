# AGENT ARCHITECTURAL & DEVELOPMENT GUIDE (.AGENT.md)

This document establishes the architecture, conventions, design decisions, and edge case strategies for the **Aarov OCR-AI Backend Service**. Any agent or engineer extending or maintaining this service must follow these patterns.

---

## 1. Project Overview & Environment

- **Service Role:** RMC (Ready-Mix Concrete) batch report OCR extraction using DeepSeek via OpenAI SDK.
- **Port:** `3050` (configured via `PORT` in `.env` / `config/constants.js`).
- **Production URL:** `https://server.aarovbuildmart.in/aiocr/`
- **Execution Mode:** Node.js ESM (`"type": "module"`), managed with PM2 (`ecosystem.config.cjs`).

---

## 2. Directory Structure & Route Pattern

All new APIs **must** be created inside modular route files under `routes/` and mounted in `server.js`. **Do not add business logic or raw endpoints directly to `server.js`.**

```
ocr-ai/
├── config/
│   └── constants.js          # Port, limits (50MB, 60 pages), concurrency slots
├── lib/
│   ├── logger.js             # Formatted timestamps & structured telemetry logging
│   ├── metrics.js            # In-memory operational metrics tracker
│   ├── openai.js             # DeepSeek client & single-page extraction
│   ├── pdf.js                # MuPDF lazy page rendering (zero disk writes)
│   └── scheduler.js          # 8-slot Semaphore & fair interleaved worker pool
├── routes/
│   ├── extract.js            # POST /api/extract, POST /api/convert-pdf
│   ├── system.js             # GET /health, GET /api/prompt, GET /
│   └── telemetry.js          # GET /dashboard, GET /api/metrics
├── server.js                 # Express bootstrap, route mounts, graceful shutdown
├── ecosystem.config.cjs      # PM2 fork mode config (1.5GB restart limit)
└── prompt.txt                # System extraction prompt
```

### How to Add a New Route
1. Create `routes/<module>.js` using an Express Router:
   ```javascript
   import { Router } from "express";
   import { logger } from "../lib/logger.js";
   
   const router = Router();
   
   router.post("/api/new-endpoint", async (req, res, next) => {
     try {
       // logic here
       res.json({ success: true });
     } catch (err) {
       next(err);
     }
   });
   
   export default router;
   ```
2. Mount it in `server.js`:
   ```javascript
   import newRoutes from "./routes/<module>.js";
   // ...
   app.use(newRoutes);
   ```

## 3. Backward Compatibility: Input Handling Rule

Clients calling `POST /api/extract` come from multiple sources (legacy web dashboards, Next.js frontend, mobile apps, local test scripts). **You must support all three input modes seamlessly:**

1. **Binary Multipart `FormData` (`req.file` via Multer)**
   - Field name: `file`
   - Zero Base64 encoding overhead (saves ~33% payload size and browser CPU time).
2. **Base64 Payload (`req.body.fileBase64`, `req.body.pdfBase64`, or `req.body.imageBase64`)**
   - Supports Data URLs (`data:application/pdf;base64,...`, `data:image/jpeg;base64,...`) and raw Base64 strings.
   - **Crucial for backward compatibility**: Existing frontend and legacy scripts sending Base64 must never break.
3. **Local File Path (`req.body.pdfPath`, `req.body.filePath`)**
   - Direct local disk path (ideal for server-side testing, batch migrations, and CLI scripts).

```javascript
// Input Resolution Priority:
// 1. req.file (Multer memoryStorage)
// 2. req.body.fileBase64 / pdfBase64 / imageBase64
// 3. req.body.filePath / pdfPath
```

## 4. Key Design Decisions

### 1. Lazy In-Memory Rendering (Zero Disk Spooling)
- **Decision:** Use MuPDF WebAssembly to render pages directly into PNG buffers on demand inside worker functions, discarding pixmaps immediately.
- **Why:** 
  - Upfront conversion of a 50-page PDF to Base64 balloons peak RAM to > 350 MB.
  - Disk spooling creates disk I/O latency, inode exhaustion, and requires cleanup crons.
  - **Result:** Peak RAM remains under **65 MB** per job, even for 50-page documents.

### 2. Fair-Interleaved Job Scheduling (Global Semaphore)
- **Decision:** Global 8-slot Semaphore (`GLOBAL_CONCURRENCY_SLOTS = 8`) combined with fair chunking (`DEFAULT_JOB_CONCURRENCY = 4` per PDF job).
- **Why:**
  - Prevents DeepSeek 429 concurrency rate limits.
  - **Eliminates Small-Job Starvation:** If User 1 uploads a 50-page PDF and User 2 uploads a 2-page PDF immediately after, User 2 does *not* wait for User 1 to finish. Both jobs interleave across the 8 slots; User 2 finishes in ~3.5 seconds.

### 3. Disabled Reasoning/Thinking Tokens for Tables
- **Decision:** Send `thinking: { type: "disabled" }` by default to DeepSeek.
- **Why:**
  - DeepSeek R1 models attempt deep reasoning on printed tabular data, generating 20,000+ internal reasoning tokens (~50s per page).
  - This routinely triggered Nginx `504 Gateway Time-out` (default 60s).
  - Disabling reasoning drops extraction time from **70s down to ~3.3s** for a 2-page PDF while cutting token consumption by 98%.

### 4. Zero-RAM Embedded Telemetry (Tier 1)
- **Decision:** In-memory operational metrics stored in circular buffers (`lib/metrics.js`), exposed via `GET /api/metrics` and rendered by a zero-overhead dark-mode dashboard at `GET /dashboard`.
- **Why:** Eliminates the need for running heavy external stacks (Prometheus, Grafana, OpenTelemetry collectors) on a 4GB RAM VPS.

### 5. Unified Response Format
- **Single-page document:** `data` is returned as a single JSON object.
- **Multi-page document:** `data` is returned as an array of JSON objects (`[ { ... }, { ... } ]`), where 1 page = 1 batch report / docket.

## 5. Edge Cases & Guardrails

| Edge Case | Threshold / Trigger | Mitigation Strategy |
| :--- | :--- | :--- |
| **Oversized File** | File > 50 MB (`MAX_FILE_SIZE_BYTES`) | Multer rejects with HTTP 400 and friendly JSON `{ error: "File exceeds 50MB limit..." }`. |
| **Excessive Page Count** | PDF > 60 pages (`MAX_PAGES_LIMIT`) | Validated upfront via MuPDF before dispatching workers; rejected immediately with HTTP 400. |
| **Concurrent Plant Traffic** | 4–5 plant operators uploading at the same minute | Global 8-slot semaphore queues excess requests; peak memory stays under ~325 MB (safe within 3.2 GB available RAM). |
| **Nginx Proxy Timeout** | Extraction exceeding 60s | Thinking tokens disabled (`< 4s` per batch). For 50-page jobs, Nginx `proxy_read_timeout 300s;` must be configured. |
| **Partial Page Failures** | Page 3 of 10 has unreadable scan | Other 9 pages succeed; failed pages are captured in `response.failed: [{ page: 3, error }]` without dropping the job. |
| **Unreadable `prompt.txt`** | File missing or bad permissions | Express server fails healthcheck (`GET /health` returns 500) and logs a critical error at startup. |
| **PM2 Process Restarts** | Unforeseen memory leak | `ecosystem.config.cjs` configured with `max_memory_restart: "1.5G"` and graceful shutdown handlers (`SIGTERM`, `SIGINT`). |
